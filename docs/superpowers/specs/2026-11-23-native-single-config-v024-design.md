## 2. 单文件交付与配置

用户只需准备 `rproxy.toml`，从唯一的 `rproxy.example.toml` 复制并填写。程序与 CLI 均支持显式 `--config rproxy.toml`。

该 TOML 包含：

- 数据目录/数据库路径、监听和 HTTPS 入口设置。
- 管理地址与管理员令牌。
- 认证模式、认证 TTL、初始用户/密码/业务授权。
- 选路、限额、验证、采集并发与周期参数。
- 初始代理来源及通用 HTTP/JSON 映射。
- 供应商专用变量表；保留来源内 `${NAME}` 引用语法。

标准使用不再需要 `.env`、`providers.env`、独立 `sources.toml` 或必须设置的进程环境变量。示例使用清晰占位值，不带共享可用默认令牌；未填写有效管理令牌必须安全失败。

CLI 从同一 TOML 取得管理 endpoint 和令牌，仍通过在线管理 API 工作，不直接打开 SQLite。显式连接选项可覆盖配置，原有自动化调用方式需保留可用的兼容路径；冲突的凭据来源不能被静默猜测。主流程及文档不依赖环境变量。

配置文件包含凭据，应放在仅服务账户可读的目录中，Unix 建议0600，Windows 使用受限 ACL；不纳入 Git，不作为发布输入。解析错误、日志和 CLI 普通输出不得回显凭据或配置原文。

## 3. 配置不是运行状态

以下仍是独立的数据/安全文件，不要求用户另行维护第二份配置：

- SQLite、可能存在的 WAL/SHM、所有权锁。
- 自动生成的来源加密密钥；继续与数据库分离保存。
- 可选 HTTPS 证书/私钥和自定义 CA，其路径写在 TOML。

不把候选池、验证结果、连接占用或 stick 绑定写回 TOML，也不把 PEM 证书内容硬塞进配置。保留单数据库单进程的所有权保护及现有 macOS/Windows sidecar、Linux inode 锁行为。

## 4. 供应商变量安全边界

供应商变量改为同一 TOML 下的专用表，例如 `[collector.variables]`。来源替换逻辑只获得该表的私有映射，不获得整个配置树，也不回退读取进程环境。

因此，即使管理员令牌和供应商变量位于同一文件，来源中的 `${NAME}` 也不能引用管理员令牌、入口密码或加密密钥，除非操作者明确把同名秘密另外放进供应商变量表。

继续限制变量数量、键和值大小、响应解压后尺寸、地址数量和采集并发。删除独立 dotenv 文件的运行依赖及其解析代码/测试后，用内联变量等价测试替代；不能仅删除安全检查。

## 5. 初始导入、在线变更与升级

- 首次初始化新数据库时，校验初始用户和来源，并导入一次。
- 用户与来源的导入完成标记持久化；全部删除后重启也不得重新创建。
- 已有数据库升级不重复导入用户，也不因新 TOML 定义而覆盖托管来源。
- 初始来源保存时保留启用状态、不可变 ID、加密配置、版本及 run generation 规则；不短暂启用声明为暂停的来源。
- 日后更新来源可通过 CLI 显式导入同一 `rproxy.toml`，使用现有 version-checked replace 语义；用户、密码与授权继续通过 user 命令显式修改。不新增隐式全量同步或后台重写 TOML。
- 单文件来源导入应复用已校验配置结构，不能把无关启动字段误作来源，也不能执行文件内容。

配置中的启动参数和供应商变量在重启后生效；SQLite 中的在线用户、来源和绑定在重启后保留。重启不会让过期凭据覆盖 CLI 改密，也不会复活已删用户或来源。

来源配置变更、认证、stick 生命周期、旧出口排空和强制撤销行为保持不变。SQLite 数据及密钥沿用现有格式，不为这次配置收敛重建数据库。

不删除用户已有的真实配置、供应商文件、数据库、私有导出、虚拟环境或忽略的缓存；不停止或清理任何无关容器、卷、镜像或 machine。
