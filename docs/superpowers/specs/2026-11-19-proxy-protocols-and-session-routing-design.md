# rproxy：协议、入口认证与会话选路设计

日期：2026-11-19
状态：用户已确认并于 2026-11-19 授权新建分支实施；首批功能已实现，验证记录见 ../verification/2026-11-19-proxy-features.md。未授权提交或推送 Git。

## 1. 目标与优先级

把当前“代理地址集合 + 随机 TCP 转发”扩展为标准客户端可使用的代理入口，优先满足：

1. HTTP 普通转发、HTTP CONNECT、HTTPS 加密代理入口及 SOCKS5 TCP CONNECT。
2. 入口用户名密码认证及匿名模式。
3. 按业务、会话选择代理，首批实现 stick、random、round-robin、shuffle。
4. 同一业务的不同会话不能共用实际出口 IP；不同业务可以复用。
5. stick 跨连接、认证续期和服务重启保持绑定，代理失效后记录日志并自动换绑。

此前讨论的完整健康治理、质量评分、供应商采购、多维选路、管理后台、完整可观测性等放 P3。不以“工程治理”为由扩大首批范围；但功能成立所必需的认证、并发分配、出口识别、协议正确性和最小测试不能省略。

## 2. 已确认需求与本设计建议的区别

### 用户已确认

- 防止未经授权的人使用入口；配置凭据后强制认证，不配置时允许匿名。
- HTTP、HTTPS 入口、CONNECT、SOCKS5 TCP CONNECT 均支持；UDP ASSOCIATE、BIND 放 P3。
- 尽可能避免代理额外引入证书问题，不要求客户端接专用 SDK。
- stick 为多个业务、多个账号分别保持出口，不是全局固定一个出口。
- 同业务不同会话出口排他，不同业务可以共享出口。
- stick 原代理失效时打日志并自动切换。
- 代理认证有可配置有效期，到期重新验证；重新验证不主动清除 stick 绑定。
- 当前上游主要为直接 IP:端口，将来可能接入同一地址轮换出口的供应商。
- 首批策略确定为 stick、random、round-robin、shuffle。

### 本设计的建议默认值，待随文档确认

- 使用标准代理用户名承载业务、会话和策略；密码单独用于入口认证。
- 业务内没有合格出口时明确失败，不自动共享、不静默改策略。
- stick 绑定持久化到 Redis，不因空闲或认证到期自动释放；提供显式释放入口。
- 上游首批保持现有 HTTP、SOCKS5 两种；HTTPS 上游作为独立扩展，不与 HTTPS 入站混淆。
- 普通 HTTP 在同一客户端连接内固定选路身份与上游，多个请求不等于多次选择；换策略或会话需新建连接。
- 认证有效期约束新请求/新建隧道，不强制切断已经建立的 CONNECT/SOCKS5 隧道。

## 3. 术语与不可破坏的约束

- 上游地址：rproxy 建立连接的 IP:端口；不等同于出口 IP。
- 出口 IP：目标侧看到的来源地址；业务内排他按规范化的实际 IP 比较，不按端口比较。
- 业务 business：需要彼此隔离出口的业务集合，由调用方明确指定。
- 会话 session：业务中的稳定账号/任务标识，由调用方指定，代理不解析目标网站账号、Cookie 或登录状态。
- 绑定：某业务、会话与上游及出口的对应关系。
- 占用：某业务的某出口当前归哪个会话使用；不同业务各自独立。

核心约束：

1. 在同一业务中，一个出口不能同时归不同会话使用。
2. 同一会话的并发 stick 连接必须获得一致绑定；故障换绑只能由一个协调流程完成。
3. 分配成功与占用写入必须是原子结果，不能先返回代理再写占用。
4. 业务标识、会话标识、策略经校验后才能选路，不允许在握手未完成或认证失败时占用资源。
5. 认证续期不等于 IP 续租，身份有效性和路由绑定独立。
6. 只能保证可控上游的固定出口；不能用“入口地址未变化”伪装出口稳定。
7. 不重放已发送的业务请求，不承诺故障时已有隧道无缝迁移。

## 4. 协议范围

### 4.1 入站

- HTTP 正向代理：正确处理 absolute-form 请求，解析目标及代理认证；支持常规请求体/响应体、连接复用和关闭语义。
- HTTP CONNECT：校验认证和目标，成功建立上游隧道后才回复成功；失败返回明确代理错误。
- HTTPS 代理入口：客户端先与 rproxy 建立 TLS，再使用同样的 HTTP 正向代理/CONNECT 能力。
- SOCKS5：方法协商、无认证、用户名密码认证、IPv4/域名/IPv6 目标、TCP CONNECT，以及成功/失败响应。
- 不支持的 SOCKS5 命令按协议明确拒绝，不挂起或误报成功。

使用成熟协议实现处理 HTTP 报文分帧和连接语义，不靠一次 read 或简单字符串替换解析完整 HTTP。

### 4.2 上游与协议适配

首批上游协议为 HTTP 和 SOCKS5。入口协议不应与同名上游池硬绑定：

- 普通 HTTP 请求可走 HTTP 上游的正向代理，也可经 SOCKS5 连接目标后发送 origin-form HTTP。
- CONNECT 和 SOCKS5 CONNECT 都表达目标 TCP 通道需求，可通过 HTTP 上游 CONNECT 或 SOCKS5 CONNECT 完成。
- HTTP 上游不一定允许 CONNECT 到任意端口，失败需如实返回，不把所有 HTTP 上游假定为任意 TCP 代理。
- 保持 stick 时，若绑定上游不能满足当前通道需求，明确返回能力不兼容；不因入口切换而偷偷更换仍健康的出口。
- 首批不要求上游用户名密码、HTTPS 上游或供应商专有协议；数据模型需允许后续扩展。入口认证秘密绝不作为上游认证转发。

普通 HTTP keep-alive 可以访问不同目标，但沿用本连接的选路结果；不同目标的上游连接建立和 HTTP 报文改写由协议适配实现。CONNECT 成功后只转发隧道字节。

### 4.3 兼容性边界

不要求 SDK、自定义 HTTP 头或客户端插件。支持具备对应协议能力的 requests/curl/浏览器及自动化客户端；不能补足客户端自身缺少的 HTTPS 代理或 SOCKS5 认证能力。

浏览器是否弹出认证窗口、自动化框架怎样传递代理认证，由客户端决定。SOCKS5 用户名长度受标准单字节长度字段限制，超长路由身份应明确拒绝。

## 5. 入口认证与有效期

### 5.1 模式

- 认证开启：所有 HTTP 请求/CONNECT 与 SOCKS5 连接均需有效凭据；SOCKS5 不能通过选择 no-auth 绕过。
- 认证关闭：HTTP 不强制凭据、SOCKS5 可协商 no-auth。匿名不等于发送空用户名密码的子协商报文。
- 凭据只配置一半、空密码歧义或配置冲突应在启动时拒绝，不能意外降级成匿名。
- HTTP 认证失败使用标准 407 与 Proxy-Authenticate；SOCKS5 使用相应协商/认证失败响应。
- 认证开启时，Redis 不可用或认证状态无法确认不能 fail-open。

首批支持配置文件管理一个或多个入口身份，不做注册、找回密码或管理后台。密码不写日志，不放 Redis 路由记录。HTTP Basic 与 SOCKS5 用户名密码在无 TLS 链路上不提供加密，应在文档注明使用边界；HTTPS 入口提供加密 HTTP 代理访问。

### 5.2 路由身份承载

建议将逻辑字段编码到标准代理用户名：入口用户、business、session、strategy。密码字段仅携带入口密码。

实现者确定无歧义的版本化语法及转义规则，并提供每种客户端的正确示例；URL 中的转义与认证报文中的原始用户名必须分清。缺失字段、未知策略、非法或超长标识明确失败，不默默生成随机会话。

- 带会话的路由需明确提供 business 和 session。
- 普通用户名不带路由字段时，可使用配置中的默认业务/策略；不得假装能识别客户端内部多个账号。
- 匿名且不携带身份时，只能使用明确的默认路由，不能承诺多个登录账号各自 stick；需要此能力的调用方必须提供可识别的路由身份。
- 配置身份对业务的允许范围；路由字段不能绕过认证、读取或覆盖其他身份拥有的绑定。
- 绑定附带入口身份归属，同一 business/session 被不同入口身份占用时拒绝；同一入口身份允许跨进程复用自己的 session。

### 5.3 有效期语义

首次成功验证后建立固定有效期，到期重新校验提供的凭据并开始下一个周期，不因流量持续到来而无限续期。有效期配置化，具体默认时长由实现者提出并在配置文档中明确。

认证期限按入口身份及凭据版本管理，不由客户端伪造时间或通过更换 session 绕过。到期校验可由客户端自动携带的相同密码完成，不承诺出现交互式登录提示；若需要强制人工重登或一次性令牌，那是另一项需求。

- 普通 HTTP：每个新请求需处于有效认证状态；同一连接不接受切换路由身份。
- CONNECT/SOCKS5：新隧道建立时验证；到期不强行中断已有隧道。
- 凭据变更/撤销后新请求应拒绝旧凭据；不要求首批强制关闭已有隧道。
- 重新验证成功仍沿用原 stick 绑定。

## 6. TLS 与证书

1. 目标 HTTPS 默认隧道透传，不解密、不替换证书，rproxy 不验证隧道内目标证书；客户端原有验证仍有效。
2. HTTPS 入口支持配置证书链和私钥，配置错误清晰报错，不静默退回明文。
3. 可信证书为优选；自签名用于受控环境，客户端需信任或显式跳过代理证书验证。服务端无法强迫客户端接受不可信证书。
4. 本池执行的检测请求可单独配置 CA/是否跳过验证；默认验证，兼容性例外显式开启，不能全局关闭所有证书检查。
5. 将来的 TLS 上游使用独立信任配置，不与入站或目标 TLS 混为一谈。

## 7. 选择策略

所有策略先过滤能力、出口可靠性及同业务占用，再选择；不因为没有候选就违反排他规则。选择粒度为新客户端代理连接/隧道，不是目标网站业务请求；一条连接不能中途换出口。

### stick

- 以 business/session 查找持久绑定；健康且能力符合就复用，不设置因空闲或认证续期触发的自动过期。
- 初次选择并原子绑定；服务重启后恢复 Redis 中的绑定。
- 连接/协议握手证实代理不可用时，协调记录故障及换绑；新连接改用合格出口。
- 原代理有意被移除视为不可继续选择，记录原因并换绑。
- 代理之外的目标失败或站点 403/未登录，不直接判为代理失效。无法区分的上游目标错误应如实返回，不贸然换绑。
- 旧连接不迁移；已有连接未结束时，旧出口不能立即分给同业务其他会话。

### random

- 每次新连接从合格候选中随机选择，并记录本会话上次出口。
- 有不同于上次的合格出口才选择；只有上次出口时明确返回无法轮换，不伪装换 IP。
- 同一会话可有多个尚未结束的不同出口连接，均归该会话占用，不能被同业务其他会话抢占。

### round-robin

- 按稳定顺序轮换候选，每业务维护游标；跳过不合格或被其他会话占用的出口。
- 是连接选择次数的轮换，不承诺字节流量均衡。
- 只有一个合格出口时允许重复，它不承诺严格每次不同。

### shuffle

- 每个业务/会话维护随机打乱的出口序列，一轮内不重复；下一轮重新洗牌，并在可行时避免与上一轮末尾连续重复。
- 序列按出口去重而不是代理端口；候选失效/被占用时跳过，不返回失效地址。
- 一轮完成后重新构建候选；仅有一个合格出口时允许重复。

round-robin/random/shuffle 的非 stick 占用随活跃连接持有并在连接结束后释放；同时保留实现策略所需的游标/上次选择记录。stick 占用持续到显式释放、换绑或代理失效清理。

策略在会话创建时确定，已有会话更改策略需显式释放并在旧连接排空后重新创建，不在并发连接间隐式混用策略。

## 8. 分配、持久化与退出

Redis 保留现有代理池兼容读写，并增加独立命名空间保存：

- 代理元数据：上游协议、能力、出口、出口稳定类型与验证状态。
- 会话绑定：business/session、入口身份归属、策略、上游、出口、绑定版本。
- 业务内出口占用及必要的连接存活记录。
- 策略状态：上次出口、轮询游标、洗牌进度。
- 认证有效期及凭据版本标识，不包含明文密码。

通过 Redis 原子操作/脚本进行分配、换绑、释放，避免多个 Rust 进程或并发连接分配冲突。持久化后的绑定能否跨 Redis 自身重启保存，取决于 Redis 持久化配置，不能由应用假定保证。

连接存活记录需要有租期/心跳以恢复崩溃遗留状态，stick 逻辑绑定不能与短租期一起自动消失。Redis 失联时不得创建无法登记的新占用；已有隧道可以继续，但实例需在租约无法安全维持前关闭受影响隧道，不能让已过期的占用与仍活跃旧连接发生冲突。具体租约、超时、脚本结构留给实施计划。

提供最小的显式会话释放入口，可采用受认证的 CLI 管理命令，不要求开发 Web 管理面；释放先阻止新连接，等活跃旧连接结束后才解除对应出口占用。

## 9. 上游出口模型与未来扩展

### 固定出口上游（首批）

优先处理直接 IP:端口，新增候选需通过可配置的出口检测确认实际 IP，不能直接拿上游地址当出口。检测目标、频率及缓存由实现者确定，需避免每次业务请求做公网探测。出口未知/验证失败的不进入要求出口排他的候选集合。

### 供应商粘性上游（未来）

供应商若提供 session 参数等能力，可用 Adapter 将本地业务会话映射到供应商会话，记录其稳定时间限制。超过供应商承诺不能继续保证永久 stick，需清晰披露。

### 不可控轮换上游（未来）

没有稳定出口保证的入口不能满足当前业务内排他约束，即使 strategy=random 也不能自动准入。单次探测不保证下一次连接仍为该出口；此类上游先标记不兼容，未来有可验证约束再接入。

首批对固定出口保证以供应商行为符合声明为前提；检测能发现变化，但无法在供应商违约时阻止所有瞬时出口变化。文档不承诺超出上游可提供的保证。

## 10. 实现组织方向

保留 Rust/Tokio 流量入口、Python 代理维护、Redis 共享状态的现有技术方向，不新增独立控制面产品。

- 协议 Module：处理 HTTP/TLS/SOCKS5 的握手、认证信息提取、目标解析及标准失败响应。
- 认证 Module：校验入口身份、业务权限、凭据版本和认证有效期，不负责释放 IP。
- 选路 Module：以已认证的业务/会话及目标能力为 Interface，内部统一策略、出口排他、持久绑定和故障换绑。
- 上游 Adapter：封装 HTTP/SOCKS5 建连及握手，将目标通道交给转发逻辑。
- Redis 是原子分配与持久状态的 Seam；不能让 HTTP 与 SOCKS5 各自复制一套选择、绑定逻辑。

具体 Rust 类型、依赖库版本、文件拆分及 Python 更新办法留给实施计划。现有缺失 list 模块、SOCKS5 采集构造错误、错误协议检查及配置不一致作为基础功能阻断项修复。

## 11. 必要失败行为与日志

- 认证失败、能力不支持、无空闲出口、严格随机无法换 IP、Redis 不可用、上游连接/握手失败均有明确结果。
- 不主动直连目标绕过代理，不降级匿名，不忽略出口排他，不把 CONNECT 上游失败当成功。
- 自动换绑日志包含业务、会话、旧/新上游及出口、原因；不含密码、完整认证头、敏感 URL。
- 建连及握手有有限超时/尝试预算；只在未发送业务数据且能够判定的阶段重选，不盲目重放请求。
- 正常隧道支持双向 EOF 和半关闭，连接结束可靠释放非 stick 活跃占用。

## 12. 验收场景

1. 普通 HTTP、HTTP CONNECT、HTTPS 入口内的两种 HTTP 模式、SOCKS5 TCP CONNECT 均完成真实收发。
2. IPv4/域名/IPv6 目标及正确的协议失败响应；不支持命令明确拒绝。
3. 正确/错误/缺失凭据和匿名模式覆盖全部入口，CONNECT 与 SOCKS5 方法选择不能绕过认证。
4. 认证到期重新验证、旧密码撤销、认证续期保持原 stick 出口；已有隧道遵循已确定的期限语义。
5. 同 business/session 跨连接和 Rust 重启保持 stick；同业务不同 session 无法抢占同一实际出口，不同业务可以共享。
6. 并发首次分配、并发故障换绑、多实例竞争及旧连接排空时不破坏出口排他。
7. stick 故障自动换绑有日志；目标 403/未登录不误触发换绑；无候选明确失败。
8. random 不与上次重复且候选不足明确失败；round-robin 次序、shuffle 一轮不重复符合定义。
9. 两个不同上游端口共享出口时不能被同业务不同会话分别占用；未知/不可控出口被排除。
10. HTTPS 入口有效证书、自签名的显式信任配置及目标 TLS 原样透传；不依赖 MITM。
11. requests/curl 及至少一种浏览器自动化客户端完成其原生支持路径；客户端自身限制明确记录。
12. 会话释放、连接半关闭、实例异常退出与 Redis 短时失联不导致错误共享或静默直连。

测试优先采用本地目标和可控假上游，避免依赖付费供应商、固定公网网站或真实账户。只做本轮约束必需的验证，不把全套治理能力提前到首批。

## 13. 明确不在首批

- SOCKS5 UDP ASSOCIATE、BIND。
- timed 策略、延迟/成功率综合评分和目标站点智能调度。
- 供应商专有粘性协议、不可控轮换上游、HTTPS 上游。
- 目标网站登录管理、Cookie 管理、验证码处理或强制网站重新登录。
- TLS 中间人解密、替换目标证书、服务端绕过客户端的证书验证。
- 完整管理后台、采购系统、多地域调度和完整监控告警平台。
