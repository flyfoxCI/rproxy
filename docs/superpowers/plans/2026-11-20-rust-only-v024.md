# Rust-only 0.2.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace all tracked Python runtime/tooling with Rust, fix macOS startup, publish v0.2.4.

**Architecture:** Internal Tokio collector uses the existing typed SQLite source plan/result seam; one production container with rproxy and CLI. A separate Rust xtask workspace member owns packaging, checksums, native and Compose verification, never ships as production binary.

**Tech Stack:** Existing Rust/Tokio/reqwest/serde/SQLite, std process; xtask tar/flate2/zip/sha2/toml/tempfile.

**Spec:** docs/superpowers/specs/2026-11-20-rust-only-v024-design.md

## Global Constraints

- Version/tag0.2.4/v0.2.4; v0.2.3 remains unpublished and immutable.
- Preserve schema2, user/source IDs, encrypted configurations, bindings and lifetime occupancy.
- No tracked .py or Python setup/workflow invocation in final code; ignored user environments/private files are untouched.
- Provider substitutions read only an explicit provider env file, never root process secrets.
- Existing credential has repo but no workflow scope; secure repo+workflow request timed out. Required CI changes cannot be silently omitted.

## Review Focus

- Same-process collection must not exfiltrate root token/master key through ${ENV}.
- Source edits/removal/manual generation/shutdown must not duplicate or resurrect network jobs.
- Darwin ownership lock cannot conflict with SQLite, but cooperative second-owner rejection must remain.
- Diagnostic/native test failures preserve redacted cause without publishing incomplete assets.
- Removing worker/Python code must not leave bootstrap/config/workflow or archive references that silently break deployment.
