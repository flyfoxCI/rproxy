# rproxy v0.2.2 changes

This document describes the v2.2 development branch (package version 0.2.2). Creating or pushing this branch does not publish a release.

## Embedded pool

- Remove the external Redis dependency and Lua routing script.
- One Rust state worker serializes typed routing operations. Bundled SQLite persists candidates, session ownership, stick bindings and strategy history before success is returned.
- Connection occupancy is process-local and lasts until the connection is released, not until a distributed lease timer expires. Old exits remain protected while old connections drain.
- Reject a second process using the same database, unsupported database versions and invalid recovered routing state. Use a local filesystem with reliable file locks, not a network share.
- Keep HTTP forward proxy, HTTP CONNECT, HTTPS proxy ingress, SOCKS5 TCP CONNECT, entry authentication and the four connection-level strategies.

## Collection and management

- Add a bearer-authenticated management listener. Candidates are not trusted as verified exits; Rust performs admission checks.
- `add-proxy`, `verify-pool`, `healthcheck` and `release-session` operate on the running process instead of opening its database.
- Replace supplier-specific Redis writers with a Python 3.11+ TOML collector. Configure GET/POST, parameters/headers/JSON body, environment references and text/JSON response mappings.
- Include Xdaili/Shenlong legacy extraction examples and generic mappings. Rola extraction requires the account's documented API and schema; credentialed gateways and supplier sticky-session parameters are not implemented.

## Docker and Podman

- One multi-stage Dockerfile, `rproxy` and `collector` image targets, and one Compose deployment without Redis.
- Read-only host configuration mounts, separate supplier environment, non-root runtime, internal-only management port and durable SQLite volume.
- Optional HTTPS override with read-only certificates; explicit SELinux labeling guidance for providers which do not forward mount relabel options.
- Document startup, host edits and force-recreate, native use, backup, troubleshooting and an isolated end-to-end Compose smoke test.

## Breaking migration

Old Redis flags, environment variables, hash writers and maintenance scripts are removed. Stop and back up an old installation before migrating. Re-import candidates through the collector or management listener. Redis stick bindings and live occupancy are not automatically migrated; this upgrade does not promise to retain old exits. Multiple machines no longer share a global allocation state.

The existing five native binary target definitions and exact-archive publication checks remain. This branch does not create a tag or overwrite any published release.
