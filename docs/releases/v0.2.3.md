# rproxy v0.2.3

## Online management

- Ship `rproxy-cli` alongside `rproxy` in all five native archives and the Rust container image.
- Manage entry users/passwords/business grants, source definitions, manual HTTP/SOCKS5 candidates and sessions through the authenticated management Interface; the CLI never opens SQLite or edits mounted server files.
- Support hidden password prompts, stdin/environment password input, safe human/JSON output, bounded waits, previews and explicit confirmation for impacting actions.
- Persist immutable user IDs and Argon2id password hashes. Password rotation invalidates subsequent authentication without releasing stick. Deleting/recreating a name cannot inherit old bindings; deleting the last user never enables anonymous access. Explicit disconnect revokes existing stream tokens.

## Sources and collector

- SQLite is the mutable user/source authority. Existing bootstrap users are imported once; restart never replaces CLI-managed credentials with old TOML values.
- Sources have revisions and acquisition generations. A limited worker credential reads plans and submits versioned results; paused, edited or deleted work is rejected atomically.
- Source configuration is encrypted with an independent key outside SQLite; normal views/exports redact literal secrets. Back up the generated private `.key` file or the external source key with the state.
- Create paused sources atomically, import old provider/new source manifests (including stdin for read-only container deployments), export configuration and trigger acquisition without restarting services.
- Preserve multiple source memberships for deduplicated proxies; source pause/remove does not implicitly withdraw existing candidates or clear stick bindings.

## Deployment and compatibility

Compose still has only Rust and collector services, with read-only host config and a durable state volume. Set a separate `RPROXY_WORKER_TOKEN`; do not pass the root admin token to collector. Startup listener/TLS/auth-policy settings remain in TOML; ordinary management changes are online.

**Upgrade from 0.2.2:** stop and back up the complete state before migration. Schema 2 preserves bindings and migrates old owner names to stable IDs. Use the new worker bootstrap TOML and explicitly import old provider manifests with the CLI. Anonymous mode now requires `auth.mode="anonymous"`; default required mode denies entry when there are no users. Downgrade requires restoring the pre-upgrade backup.

Redis-era bindings are still not automatically imported. Upstream HTTPS, upstream username/password, supplier rotating/sticky gateways, UDP/BIND, multi-machine allocation and a Web administration UI remain unsupported.

Release assets contain both executables for Linux x86_64/ARM64 (musl), macOS Intel/Apple Silicon (11.0+, unsigned/not notarized), and Windows x86_64. Native startup checks, both-binary archive validation, exact five-package completeness and SHA256SUMS gate publication. Existing releases/tags are not overwritten.
