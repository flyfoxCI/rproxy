# rproxy v0.2.4

## Rust-only acquisition and deployment

- Move generic provider acquisition into rproxy's Tokio runtime; retain GET/POST, text/JSON mappings, per-source TLS policy and bounded retries. No provider-specific classes or invented supplier endpoints.
- Preserve SQLite schema2, encrypted source configurations, immutable user/source IDs, managed passwords and stick bindings. Existing CLI management remains online.
- Provider `${ENV}` substitution reads only a dedicated bounded UTF-8 file, never general process environment containing root/master secrets. Relative paths resolve against the server TOML.
- Bound concurrent jobs, response size after decompression, extracted addresses and submissions. Cancel obsolete/shutdown work; atomically reject stale source revisions/generations on every batch.
- Remove the external collector HTTP API and worker authentication. The old `worker_token_env` startup field is parsed only for compatibility and grants no access.
- One production Compose service and two shipped binaries (`rproxy`, `rproxy-cli`). Configuration and provider files stay on the host with read-only mounts; SQLite and its encryption key stay on the existing persistent volume.
- Replace tracked acquisition, fixture, Compose smoke and packaging scripts with Rust tests and a development-only `xtask` workspace member. No runtime interpreter, dependency requirements or external state service.
- Replace per-source one-shot acquisition with `rproxy-cli source run --wait`; there is no separate worker executable or all-sources `--once` command. Startup checks use `rproxy check-config`.
- Protocol/TLS integration tests replace the Python protocol smoke; the former requests/optional Playwright client matrix is not retained and is not fresh browser-compatibility evidence.
- Fix provider-variable file resolution when the server config itself has a relative parent directory; resolve paths once against the server TOML directory.

## Native startup and release safety

- Fix macOS SQLite startup: use a sidecar ownership lock instead of flock on the SQLite inode. Linux retains its database-inode lock, Windows its sidecar. Never remove live lock/database files.
- Keep five native targets: Linux x86_64/ARM64 musl, macOS Intel/Apple Silicon and Windows x86_64 MSVC.
- Preserve x86_64 musl's working default Rust linker; ARM64 continues to select musl-gcc explicitly.
- Rust release tooling checks trusted locally built daemon/CLI versions and real SQLite/CLI startup before packaging. Archive verification never executes downloaded or archived programs.
- Verify exact five-archive membership, both executable files, safe regular paths/modes and SHA256SUMS before publishing a draft. Public releases are not overwritten.
- v0.2.3 remains unpublished with its original tag; no older tag is moved.

## Upgrade

Back up the stopped deployment's entire state directory (including WAL/key files) and configuration. Keep the same Compose project and volume. Add `[collector]` to rproxy.toml, migrate supplier variables to providers.env, remove the worker token/bootstrap reference and the old worker container. Existing managed sources do not need reimporting. The 0.2.2 user migration remains bootstrap-once; it does not overwrite CLI changes.

See README.md and docs/collector-management.md for startup, source import and security boundaries. Release availability and verification status are determined by the actual workflow and assets, not by the presence of these notes.
