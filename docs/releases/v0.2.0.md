# rproxy v0.2.0

## 协议与入口认证

- HTTP 正向代理、HTTPS CONNECT、TLS 加密的 HTTPS 代理入口。
- SOCKS5 TCP CONNECT，支持 IPv4、域名和 IPv6 目标。
- 标准 HTTP Basic / SOCKS5 用户名密码认证及匿名模式；开启认证后不能绕过。
- HTTP 与 SOCKS5 上游适配；HTTPS 目标原样透传，不做 TLS 中间人解密。

## 多业务会话与选路

- `stick`、`random`、`round-robin`、`shuffle` 四种连接级策略。
- 标准代理用户名 `v1|用户|业务|会话|策略`，兼容常规客户端，不要求 SDK。
- 同业务的不同会话不能共享实际出口 IP；不同业务可以共享。
- Redis 原子分配、持久 stick 绑定、并发故障换绑、连接租约和排空后释放。
- 认证有效期与 IP 绑定独立，认证续期不主动更换仍有效的出口。

## 运维与兼容性

- 出口检测、配置检查、会话释放命令。
- 修复 SOCKS5 采集、容量限制、检测重试、状态更新和连接关闭问题。
- 示例配置、requests/curl/Playwright 使用说明及可执行程序烟测脚本。
- Linux x64 静态 musl 包和 Windows x64 MSVC 包，内含程序、示例配置、README 与 Python 维护脚本。
- `SHA256SUMS` 提供发布包的 SHA-256 校验值。源代码压缩包由 GitHub 自动提供。

## 升级注意

- Python 维护脚本要求 Python 3.10+，采集和检查脚本的 `-e` 均为秒。
- 需要 Redis（Lua/cjson）；多个实例可共享单机 Redis，不支持 Redis Cluster 跨槽路由脚本。
- 原有 `proxy:pool:http` / `proxy:pool:socks5` 保持兼容；地址需通过实际出口检测后才参与选路。
- `random` 按新 TCP 连接选择，不是每个复用连接内的 HTTP 请求；没有不同出口时明确失败。
- 使用前复制 `rproxy.example.toml` 并修改入口密码、Redis 地址及证书；不要公开匿名入口。
- 自签名代理证书需客户端显式信任；固定出口保证依赖上游供应商实际能力。

SOCKS5 UDP/BIND、HTTPS 上游、供应商专有粘性接入及完整池治理仍为后续范围。

## 验证

本地验证覆盖 40 个 Rust 测试、Python 维护与发布打包测试、严格 Clippy、release 构建及 requests/curl/Chromium 的实际客户端访问。GitHub 发布流水线再次执行 CI、构建两个目标并校验归档后，才公开 Release。
